ai-hooks numbers: detection, false alarms, latency

Measured on one machine: Intel Core Ultra 7 155H, 22 threads, Linux 7.2, Go 1.27.4, while it was busy with other work (load average 7 to 12). Read them as conservative. Reproduce with make selftest and make latency. The per-type table is in docs/DETECTION.md.

MeasureResult
Detection, bundled corpus123/123 fake secrets redacted, across 113 detector types
False alarms, bundled corpus0/43 clean samples touched
Known misses5: a bare TOKEN=value, a base64-encoded key, a key split by spaces, a password in prose, a value under the minimum length
Known false alarms2: md5sum output (bare 32-hex), password = getpass.getpass(...) in code
Binary size3.9 MB, linux/amd64, stripped, static, no dependencies
Cold start, hook, allowed command5.2 ms mean, 6.1 ms p95 (150 launches) with the machine lightly loaded, against 4.0 ms for a bare process start; at load average 12: 13.7 ms against 13.0 ms. The tool adds roughly 1 to 6 ms to the cost of starting a process.
Throughputredact on a 10 MB log with a few secrets: 9 to 12 s of CPU at load average 17 (about 1 MB/s). Built for command output, not log archives.
Cold start, redact, small textabout 10 ms; the Python original it descends from: 91 ms
Output vs the original shape detectorsbyte-identical in compatibility mode (AI_HOOKS_PARITY=1) on 20,000 synthetic texts and thousands of real text files; see PARITY.md in the repository

The corpus is small and written by the authors. It shows the tool does what it says on known shapes, not how it will do on your data. False-alarm reports with a fake example are the most useful contribution.

ai-hooks is Apache-2.0. Source · Built and used daily at KOA Labs.
